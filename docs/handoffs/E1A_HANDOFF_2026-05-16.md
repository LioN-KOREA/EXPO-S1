### API 컨트랙트 (preserve 필수)

**attendance** (`/api/attendance/*`)
- `POST /create-by-date` — 일자별 출석표 자동 생성 (admin)
- `GET /` — 출석 리스트 (admin, query: event_id, date?, account_type?)
- `GET /count` — 상태별 카운트 (admin, dashboard)
- `PATCH /:id/status` — 상태 변경 + 감사 로그
- `PATCH /:id/eval` — 근태평가
- `POST /send-message-schedule` — 출석 메시지 예약 (스텁)
- `POST /qr-scan` — QR 스캔 출석 (admin, interpreter)

**satisfaction** (`/api/satisfaction/*`)
- `GET /forms?event_id&target_type&stage` — 폼 리스트 (all roles)
- `GET /forms/:id` — 폼 단건
- `POST /forms` — 폼 생성 (admin)
- `PATCH /forms/:id` — 폼 수정 (admin)
- `GET /responses?form_id` — 응답 리스트 (admin: 전체, 사용자: 본인만)
- `POST /responses` — 응답 제출/수정

**notice** (`/api/notice/*`)
- `POST /` — 공지 발송 (admin)
- `GET /` — 보낸 공지함 (admin)
- `GET /my?event_id?` — 받은 공지 (all roles)
- `PATCH /:id/read` — 읽음 표시
- `GET /:id/read-stats` — 읽음 통계 (admin)

**message** (`/api/message/*`)
- `GET /templates?type?` — 템플릿 리스트
- `POST /templates` — 템플릿 생성
- `POST /send` — 메시지 발송 (어댑터 스텁)
- `GET /logs?event_id?&status?` — 발송 이력

### 기술적 특이사항
- 데이터 접근: 모두 `SupabaseService.getAdminClient()` 사용 (RLS 우회). Repository 패턴
- 인증: `AuthGuard` + `@Roles(...)` 데코레이터. `req.user.id`, `req.profile.role` 사용
- DTO 없음 — inline `@Body() body: {...}` 패턴
- 스텁 기능: attendance.send-message-schedule, message.send (실제 외부 발송 호출 X, `message_logs` PENDING insert만)

### 이식 시 고려
- Lambda 함수 단위 분할 vs Express/Fastify 래퍼 단일 함수?
- AuthGuard → API Gateway authorizer 또는 함수 내 JWT 검증
- supabase-js (Service Role Key) 환경변수 주입
