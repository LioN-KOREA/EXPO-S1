### Codex 검수 사이클 = 3회
| 회차 | 결과 | 조치 |
|---|---|---|
| 1 | HIGH 1 (SQS revalidation queue 부재), MEDIUM 1 (`@latest` 부동), LOW 1 (streaming 주석) | open-next.config.ts 신규, `@^3` 핀, 주석 수정 |
| 2 | LOW 2 (`queue: "dummy"` 호출 시 throw, revalidateTag no-op 주석 오기) | custom no-op queue 함수, 주석 정확화 |
| 3 | MEDIUM 2 (lazy loader 비동기 누락, devDep 미등록) | `async` 추가, `@opennextjs/aws@^3` devDep 추가 |
| 최종 | tsc --noEmit EXIT=0 | 통과 |

### Why queue=noop (custom send: async () => {})
- 레거시 `open-next` 패키지가 SQS 없이 동작했음 → ISR 의미 보존 = "STALE 시 다음 요청 동기 refresh"
- OpenNext v3 의 built-in `queue: "dummy"` = send 호출 시 throw → 현재 repo 에는 route-level ISR 없어 안전하지만 향후 `export const revalidate = N` 추가 시 SSR Lambda 깨짐. 미래 위험 제거 목적
- `unstable_cache(..., {revalidate:N})` + `revalidateTag()` 는 무관 (S3 + DynamoDB incremental/tag cache 사용)

## 3. Pulumi passphrase 복구

### 원인
- `Pulumi.e1s.yaml` 의 `encryptionsalt` 가 `acaee70` 커밋 (5/29, "Pulumi e1s 스택 시크릿 채움") 에서 신규 생성
- GitHub Secret `PULUMI_CONFIG_PASSPHRASE` 는 5/19 등록 상태 그대로 → 둘이 불일치
- 5/29 푸시 + 본 세션 1차 푸시 (`cca9803`) Deploy 모두 동일 에러: `error: getting stack configuration: get stack secrets manager: incorrect passphrase`

### 복구
1. `gh secret set PULUMI_CONFIG_PASSPHRASE` (PowerShell `Read-Host -AsSecureString` 스트림으로 채팅 평문 노출 0)
2. 1차 시도 = literal "passphrase" 단어 입력 → Deploy 실패 (`incorrect ***`)
3. 메모리/세션히스토리 grep 으로 acaee70 와 같은 표준 passphrase = `excon-pulumi-2026-05` 발견 (`memory/project_aws_deployment.md:22`, `session-history/2026-05-19.md:77`)
4. 2차 시도 = 정값 입력 → `gh workflow run "Deploy (prod)"` 트리거 (run 26732508413)

### 보안 부채 (후속 회전 권장)
- Pulumi passphrase 평문이 두 곳에 보존 중: `memory/project_aws_deployment.md`, `docs/session-history/2026-05-19.md`
- 1차 시도의 literal "passphrase" 값도 잠시 secret 로 set 됐다가 덮어쓰기됨 (회전 시 의미 없으나 GitHub audit log 에 남음)
- 후속 = 신규 passphrase 정해서 stack secrets 재인코딩 + GitHub Secret 갱신 + 메모리/session-history 평문 제거
