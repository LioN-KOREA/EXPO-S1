### 7. 모바일 QR race + error boundary (`42483d2`)

**증상 #1:** Android Chrome 통역사가 "QR코드로 출석하기" 클릭 → "This page couldn't load" 페이지 크래시.

**원인:** `QrScannerModal` useEffect deps 에 `status` 포함 → `setStatus()` 호출마다 useEffect 재실행 → 매 사이클마다 html5-qrcode 인스턴스 cleanup+recreate → 카메라 스트림 반복 생성/파괴 → Android Chrome renderer 크래시.

**수정 (Codex 8차 검수 반복 → 통과):**
- useEffect deps 정리 (ref 패턴: statusRef/onSuccessRef/eventIdRef)
- 세션별 closure flag `aborted` + 로컬 `myScanner` 인스턴스 (세션 격리)
- `safeDispose` 헬퍼 (html5-qrcode stop/clear 의 sync throw + Promise reject 둘 다 try-catch)
- `registerDispose` 헬퍼 (모든 dispose 경로 = handleScanned terminal / start abort / start fail / post-resolve abort / cleanup 가 동일 `pendingDisposeRef` chain 통과)
- `startBarrier` (in-flight scanner.start() promise 캡처 → chain 에 포함)
- `disposeOnce` IIFE (idempotent 정리, onSuccess 콜백 throw 시도 안전)
- handleScanned guard: `statusRef.current !== 'scanning'` 로 변경 (error 포함 모든 terminal 차단)
- `interpreter/error.tsx` 신규 — ChunkLoadError 광역 감지 (Loading chunk/CSS chunk/Failed to fetch dynamically/error loading dynamically/Importing a module script failed/Unable to preload CSS) + 새로고침 버튼

### 8. QR 카메라 권한 진단 + 사이드메뉴 QR 스텁 제거 (`269eefc`)

**증상 #2:** 사용자 보고 — "카메라를 시작할 수 없습니다"만 뜨고 허용 prompt 자체가 안 나옴.

**진단:** 운영 응답 헤더 직접 curl 확인 → Permissions-Policy 헤더 없음 → CloudFront 차단 X. 원인은 브라우저의 권한 캐시(이전 거부) 또는 사용자가 차단 상태.

**수정:**
- `next.config.ts` headers() — `Permissions-Policy: camera=(self), microphone=(), geolocation=()` 명시 (예방적 안전장치)
- `QrScannerModal start()` 첫머리에 사전 환경 검사:
  - `window.isSecureContext` / `mediaDevices.getUserMedia` 존재 사전 체크
  - **직접 `getUserMedia` 호출**로 권한 prompt 강제 + DOMException name 으로 사유 구분
  - `NotAllowedError`/`SecurityError` → 메시지에 "Permissions Policy" 패턴 있으면 정책 차단 안내, 아니면 권한 거부 안내
  - `NotFoundError`/`OverconstrainedError` → 카메라 없음
  - `NotReadableError` → 다른 앱 사용 중
  - 알 수 없는 에러 → 원본 메시지 유지 + `console.warn` 로깅 (운영 디버깅)
- 신규 i18n 6키 (ko/en): `cameraInsecureContext`, `cameraApiUnavailable`, `cameraPermissionDenied`, `cameraPolicyBlocked`, `cameraNotFound`, `cameraInUse`
- `InterpreterSideMenu` — "QR코드 스캔" + "내 QR코드" 스텁 버튼 제거 (사용자 요청, 토스트 "준비중 (Phase E-2)" 만 뜨던 미구현). 미사용 import + i18n 키 4개 정리

**사용자 확인:** 수동으로 카메라 권한 허용한 후 QR 스캔 진행됐지만 → 새 버그 발견.

### 9. 통역사 본인 QR 출석 RLS 허용 (`6aab0c2`) — **마이그 038 운영 적용 완료**

**증상 #3:** QR 스캔 후 `new row violates row-level security policy for table "attendances"` 에러.

**원인:** `019_attendance.sql` 의 attendances INSERT 정책이 admin only. 통역사 본인이 출석 INSERT 차단됨.

**수정 (Codex 3차 검수 반영):**
- **마이그 038**: `attendances_insert_self_qr` 정책 신규 — 통역사 본인 QR 출석에 한해 INSERT 허용. 보안 제약 9가지:
  - `user_id = auth.uid()` — 본인 행만
  - `account_type = 'INTERPRETER'` — SELLER 위장 차단
  - `status = 'WAITING'` — DONE/LEAVE 등 운영 상태 위조 차단
  - `work_type = 'REGULAR'` — RESERVE 위장 차단
  - `eval IS NULL` / `memo IS NULL` / `booth_id IS NULL` — 평가·메모·부스 위조 차단
  - `date = CURRENT_DATE` — 과거/미래 출석 위조 차단
  - profile role = 'interpreter'
  - `event_interpreters` 매핑 존재 — 본인 배정 행사만
  - events 활성 (deleted_at IS NULL) + 기간 내 — 종료/예정 행사 출석 위조 차단
- `QrScannerModal` upsert `ignoreDuplicates: false → true` — UPDATE 권한은 admin 만이라 같은 날 중복 스캔 시 UNIQUE 충돌 → 자연 skip (첫 출석만 기록)

**운영 적용:** `npx supabase db push --linked` 로 마이그 038 운영 DB 적용 완료.

**후속 강화 (Phase F 추후):**
- QR signed nonce / one-time token — 현재는 event_id 만 알면 QR 스캔 없이도 출석 가능 (배정된 통역사는 무난한 정도 위험)
- `created_at` 서버시간 강제 trigger — 클라이언트가 임의 timestamp 주입 가능 (현재 코드에선 안 보내고 있음)
