## 주요 결정사항

### 1. 스토리보드 기반 업그레이드 방향 (본 작업, 미시작)
- `input/0514 사이트 스토리보드/STORYBOARD.md` 13페이지 사양 ↔ 현재 사이트 갭 분석

- 다음 세션에서 본격 착수

### 2. 프로젝트 전용 서브에이전트 구조
- **3분류**: 디자인 / 코딩 / UI
- 코딩 에이전트는 **Next.js 기준** (현재 운영 스택, NestJS 전환은 진행 중이지만 보류)
- 프론트엔드·백엔드 분리 에이전트는 **이번엔 안 만듦** (NestJS 전환 진척에 맞춰 추후)
- 핵심: **각 에이전트의 결과물 품질**이 중요. 강제 규칙은 최소화

### 3. 디자인 규칙 재해석 (중요)
- 기존 메모리 `feedback_dashboard_design` 의 "파이차트 금지 / 수평바 사용" 은 **강제 룰이 아님**
- 사용자 본의: "이전에 디자인/UI 자체 품질이 낮아서 그런 룰이 나온 것. 품질 좋으면 차트 종류 자유"
- 새 에이전트들은 품질 우선, 룰은 가이드 수준

### 4. .md 파일 분량 룰 (글로벌)
- 모든 .md 파일은 **60-70줄** 사이로 작성
- 예외: 세션 히스토리 파일(`session-history/*.md`), 세션복기 에이전트 정의 파일은 분량 제한 없음

### 5. 세션 히스토리 분리 관리
- `MEMORY.md`는 너무 추상적 → 구체 맥락은 별도 폴더로 시간순 기록
- 위치: 프로젝트 루트의 `session-history/`
- 형식: `YYYY-MM-DD.md`
- 읽기·저장 글로벌 에이전트(`세션복기`) 신규 작성
